把免费的代码托管仓库当**文件仓库**用：图片在本机用多核 CPU 压缩好再推上去，其他文件原样上传。

3.3.0 把**上传这条链路**从头到尾重做了一遍：进度看得见了、大文件自动分批、
CNB 还能把文件存进对象存储。顺带补上了浅色毛玻璃的智能调参。

## 上传终于看得见进度

以前点「开始上传」，只有一条自己转圈的进度条，转完弹个「成功」——
中间那几十秒在干什么完全不知道（CNB 走 git 通道，克隆、打包、推送都在后端）。

现在是一条**真进度**：`上传中 45% · 12.3/27.4 MB · 2.1 MB/s · 约 7 秒`。
数字是后端报上来的：CNB 解析 `git push` 的输出，GitHub 按文件字节算，
两条链路汇到同一条进度流里。

在准备阶段（后端还没算出总量时）显示流动条纹而不是假的 0% ——
硬画一个 0% 会让人以为卡死了。

## CNB 大文件可以走对象存储（LFS）

上传页多了一个「用 LFS 对象存储」开关（**只在 CNB 平台出现**，GitHub 没有这个）。

打开后文件内容进 CNB 的**对象存储**，仓库里只留一个一百多字节的指针。好处是实打实的：

- **对象存储和仓库存储是两笔独立额度**（各 100 GiB），大文件不占仓库那份
- 别人 clone 仓库时不会被几百 MB 的大文件拖死

实测过：一个 200 MB 的文件，不走 LFS 时仓库里实打实多 200 MB；
走 LFS 时 git 仓库**一个字节都没多**，内容全在对象存储那边。

git-lfs 不用自己装 —— 第一次勾选会自动下载（约 6 MB，解压到配置目录，
不动系统、不要管理员权限）。设置页也能看到它装没装。

## 一次拖进来很多大文件？自动分批

后端有 512 MB 的请求体上限（防止一个请求把内存吃光）。以前一次拖 10 个
200 MB 进来会直接撞上，只能自己手动分组。

现在会自动切开：10 × 200 MB 会分成 10 批依次传，进度条跨批次累计、
**只走一次 0→100%**（不会每批都从零开始跳）。

顺带把内存峰值也降下来了 —— 以前要把所有文件一次性转成 base64
（10 × 200 MB 就是 2.7 GB 的字符串），现在逐批转，峰值只有单批的量。

## 「上传到此文件夹」也一视同仁

文件管理页右键那个 mini 上传弹窗，以前是个简化版：没有 LFS 开关、
没有真进度条。现在和上传页**完全是同一套逻辑**——包括记住你的勾选
（在主页面勾了，右键弹窗打开也是勾上的）。

## 浅色毛玻璃会自己调参了

设置 → 外观里多了一个「分析背景图」按钮。点一下它会算这张图的亮度、
饱和度、对比度和色调倾向，然后给出推荐的毛玻璃强度。

暗图会糊得更狠、白纱更厚、文字自动加重并加一圈微光晕；亮图反过来。
原理写在注释里了，简单说就是：以前只有一个「背景偏暗 → 加厚白纱」的
二分判断，现在是四个指标一起算，普通照片也不会调出「发白」或「发灰」的效果。

## 修掉的坑

- **LFS 上传其实完全用不了**：之前写的是 `git lfs track --force`，
  而这个参数**根本不存在**，执行会直接报错。编译能过、自检能过、界面看着也正常，
  只有真正跑一次 `git lfs track` 才会暴露 —— 为此补了几个真实调 git 的测试。
- **「恢复默认设置」不会误删 Token 了**（这条是 3.2.0 的补丁，一并说明）。
- 清理了一批早就没用的死代码（Go 侧 4 处、CSS 侧 7 个类 + 3 处重复定义）。

## 安装

下载下方的 `QuickFileDispatch-Setup-3.3.0.exe` 双击安装即可。

- 系统要求：Windows 10 / 11（x64）
- 建议装好 Git（CNB 平台的写入依赖它；没装也能浏览云端，只是慢一些）
- 首次启动进入新手指引：选平台 → 填仓库与令牌（现场验证）→ 映射本地目录
