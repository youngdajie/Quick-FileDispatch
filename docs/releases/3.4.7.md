## 修：GitHub 上传一直报「仓库或分支不存在」

症状很误导人：首页传一张图，报

> 仓库或分支不存在：请检查用户名 / 仓库名 / 分支名，以及 Token 是否可访问该私有仓库

可名字、分支、令牌全是对的 —— 而且**同一份配置在「文件管理」页推送一切正常**。

真正的原因是：GitHub 的「读分支引用」和「更新分支引用」是**两个不同的接口**，
路径只差一个字母（`/git/ref/` 对 `/git/refs/`）。代码里这两处共用了同一个路径，
于是整个上传过程是：

```
把文件内容传上去   ✓
建好目录树         ✓
建好提交           ✓
更新分支指向新提交 ✗ ← 404
```

**最后一步**才失败，所以报出来的错指向分支，而分支一点问题都没有。
「文件管理」页走的是本地 git、不碰这个接口，自然一切正常 —— 这也解释了
为什么"能推"和"传不上"能同时成立。

这一版把两处路径都改正了，「改名 / 移动」也受益（走的是同一套接口）。

## 新：网络代理

以前程序**不跟系统代理走**。Windows 的「设置 → 代理」存在注册表里，
本程序不读它 —— 而 Clash / v2rayN 这类工具默认改的正是那一项。
结果就是：浏览器一切正常、程序却连不上，报的还是一些跟代理毫无关系的错。

现在「设置 → 网络代理」里填上地址就行：

- 常见填法 `127.0.0.1:7890`（Clash 默认的 HTTP 端口）或 `socks5://127.0.0.1:7891`
- 上传、推送、下载 git-lfs 都会走它，**改完立即生效、不用重启**
- **CNB 不受影响**：它是国内平台，流量一律直连 —— 走代理只会更慢
